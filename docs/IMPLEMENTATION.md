# Warehouse Play 10 — 구현 기록

## 원본과 변경 원칙

기준 커밋: `4ec7c8e42bf1122dea3798a6bfefc257cd0c4ec1`. 기존 정밀 편집기 HTML을 `advanced.html`로 복사하고 새 기본 화면을 별도로 만들었다. 기존 app.js/styles.css/기준 도면은 유지했다. 라이브러리와 모델 파일의 잘린 꼬리 부분 때문에 원본에서 SyntaxError가 발생했다. Three.js core는 공식 0.185.0 배포본으로 대체하고 누락된 모델 레지스트리, 컴퓨터·안전설비·작업자·박스 적재 빌더와 적재 계산을 복원했다.

## 데이터·저장

schemaVersion 10은 schema7의 x/y 바닥 좌표, z 고도, 회전 각도(도), 규격(m)을 따른다. 새 simulation 필드는 workers/speed/stations 4개로 구성한다. 가져오기는 검증된 새 객체를 만든 뒤 원자적으로 UI에 적용한다. 잘못된 입력은 현재 도면을 먼저 지우지 않는다. 제목과 설비명은 DOM textContent 또는 canvas 텍스트로 처리한다.

기존 키와 새 로컬 키를 분리한다. 초기화에서 읽지 못한 손상 초안은 편집을 시작하기 전에는 덮어쓰지 않는다. 공유 링크 방문은 본인 로컬 초안을 교체하지 않는다. 모드별 일시정지·재생 상태와 작업자 좌표는 영구 도면이 아니라 실행 상태다.

GitHubStore는 고정 API 호스트, 유효성 검사된 owner/repo/branch, 고정 projects/ 하위의 안전한 JSON 파일명만 사용한다. 토큰은 private field에만 있고 fetch에 전달할 때만 사용한다. 브라우저 fetch는 globalThis에 바인딩하여 Illegal invocation을 방지한다. 저장은 동시에 하나만 수행한다. SHA는 마지막 정상 불러오기/저장의 값만 사용하며, 파일 존재를 확인해서 최신 SHA로 몰래 덮어쓰지 않는다. API 409/422는 충돌로 보고하고 명시적인 새 이름 저장/다시 불러오기를 요구한다.

## 경로·충돌·시뮬레이션

회전된 직사각형의 SAT로 설비 겹침을 검사하고 보행 원과 OBB 간 거리로 보행 충돌을 계산한다. 이동은 0.12m 이하로 잘라 얇은 벽을 통과하지 않도록 한다. 경계에 닿으면 축 방향으로 미끄러진다. 수직 점유도 일부 반영하지만 상층 보행이나 상세 메시 내부는 계산하지 않는다.

경로 격자는 기본 0.5m, 큰 도면에서는 최대 변을 200칸 수준으로 분할한다. 작업자 반경 및 여유를 반영하고 각 연결 선분도 충돌 검사한다. A*는 4방향 이동만 허용해 대각선 모서리를 가로지르지 않는다. 지점은 가까운 도달 가능한 셀로 스냅한다. 접근 가능한 목적지가 없으면 blocked 상태로 멈추며 순간이동하거나 사이클을 세지 않는다.

시뮬레이션은 실제 누적된 simulated dt와 거리만 센다. 1.15m/s의 단순 보행, 단계별 일정 대기, 단계 순환을 사용한다. 작업자는 랙을 피하지만 작업자끼리의 교통/충돌, 실제 작업 표준시간, 지게차 흐름은 모델링하지 않는다. 처리량/소방법/구조 안전 판단용 수치가 아니다.

## 1인칭 및 렌더링

Three.js PerspectiveCamera, WASD와 normalized diagonal movement, yaw/pitch, 1.65m 눈높이, 프레임 시간 상한 및 하위 이동 스텝을 사용한다. 시작 위치는 빈 셀을 찾고, 진입 전 OrbitControls 카메라를 저장해 나갈 때 복원한다. pointer lock은 클릭으로만 요청하며 미지원 시 드래그 시점이 남는다. blur/visibility change/pointer lock 해제에서 키 상태를 초기화한다. 모바일에는 방향 버튼과 스와이프가 있다.

설비와 작업자 메시를 매 프레임 새로 만들지 않는다. 작업자 팔다리만 회전시키고, 경로 선은 경로가 바뀔 때만 교체한다. 메쉬 제거 시 geometry/material/texture를 해제한다. 편집 시 전체 장면을 재구축하는 방식이므로 수백 개의 복잡한 설비에서는 성능 여유가 줄어든다.

## 검증의 경계

- Node 단위 검사는 유효성/마이그레이션/회전 충돌/통로/얇은 벽/A*/작업 사이클/정지·초기화/한글 인코딩/인증 오류/충돌/직렬 저장을 검사한다.
- Playwright는 실제 Chromium WebGL(테스트 호스트의 SwiftShader)에서 화면과 입력을 검사한다. 본체를 가짜 이미지로 대체하지 않는다.
- 빠른 완주와 경계 재현에는 `?test=1`일 때만 노출되는 deterministic advance 및 안전하지 않은 테스트용 위치 설정 훅을 사용한다. 운영 일반 URL에서는 노출되지 않는다. 키보드/터치/드래그 이동은 실제 DOM 입력으로 검사한다.
- GitHub 저장 UI 테스트는 모의 응답을 사용한다. 별도 임시 브랜치에서 실제 Contents API 파일 생성/UTF-8 읽기/수정/오래된 SHA 충돌을 검사하고 브랜치를 삭제한다. 이 단계는 인증된 GitHub CLI가 수행하며 브라우저에 실제 토큰을 주입하지 않는다.
- 실제 휴대폰 성능, iOS Safari, 대규모 도면 성능, 다중 작업자 교통 모델, 사내 망 접근, 회사 보안/저장 정책은 검증 범위 밖이다.

## 유지보수 시 주의

새 설비 추가 시 studio-catalog.js와 objects.js의 정의를 함께 갱신해야 한다. 두 편집기의 기존 계약을 갑자기 변경하지 말 것. 지원을 늘릴 때 실제 meshes와 점유 영역이 맞는지 확인할 것. 정밀 편집기 재저장은 신규 simulation 필드를 유지하지 않으므로 마이그레이션 작업을 별도로 하지 않는 한 서로 JSON 교환용으로만 설명할 것. 사용자의 토큰·실제 민감 도면을 테스트/스크린샷/로그/커밋에 넣지 말 것.
