# 업무형 창고 설계 워크벤치

창고 규격을 정하고, 설비를 배치하고, 수량과 공간을 검토한 뒤 도면을 저장하는 작업 흐름을 제공합니다. 이 문서는 `city-workbench.mjs`, `city-insights.mjs`, `city-fallback.mjs`에 구현된 화면과 계산 기준을 설명합니다.

## 화면에서 달라진 점

| 기능 | 업무에서 사용하는 방법 |
| --- | --- |
| 설비 · 자동 배치 · 프로젝트 탭 | 설비 검색, 반복 배치, 도면 시작·불러오기를 목적별로 찾습니다. |
| 창고 현황 · 설비 속성 탭 | 전체 수량과 선택한 설비의 위치·규격을 나눠 확인합니다. |
| 배치한 설비 목록 | 이름으로 검색한 후 항목을 누르면 해당 설비를 선택하고 화면을 이동합니다. |
| 선택 설비 도구 | 화면 안에서 회전·복제·삭제를 실행합니다. 잠긴 설비는 먼저 속성에서 잠금을 해제합니다. |
| 기능 검색 | `Ctrl+K` 또는 `⌘+K`로 열어 “수량표”, “랙”, “저장”처럼 검색합니다. 방향키와 Enter로 실행할 수 있습니다. |
| 배치 검토 | 창고 경계, 설비 겹침, 표시한 통로의 폭과 침범을 확인하고 문제 설비로 이동합니다. |
| 설비 수량표 | 동일한 종류·규격·설정끼리 집계하고 한글 CSV로 내려받습니다. 보관 가능 위치와 배치된 박스를 구분합니다. |
| 설계안 비교 | 현재 작업과 브라우저에 보관한 최대 5개 안의 팔레트 위치, 설비 수, 바닥 점유율을 비교합니다. |
| 사용법 | 처음 시작하는 순서와 기본 단축키를 화면 안에서 확인합니다. |

## 처음 도면을 만드는 순서

1. **프로젝트**에서 표준 물류센터 템플릿 또는 빈 창고로 시작합니다. 기존 작업은 먼저 **JSON**으로 내보내 보관합니다.
2. 오른쪽 **창고 현황 → 창고 규격**에서 가로·세로·높이를 입력합니다. 편집 화면의 길이 단위는 **m**입니다.
3. 왼쪽 **설비**에서 검색하거나 분류를 고른 뒤 바닥을 클릭해 배치합니다. 배치 중 `R`로 회전하고 `Esc`로 취소합니다. 놓인 설비를 선택하면 오른쪽 **설비 속성**에서 정확한 위치와 크기를 조정할 수 있습니다.
4. 반복해서 놓을 랙은 **자동 배치 → 랙 구역 자동 배치**를 엽니다. 행 수·랙 크기·통로 폭 등을 입력하고 **배치 미리보기**의 수량과 오류를 확인한 뒤 적용합니다. 팔레트·박스 구역 채우기와 적재 계산은 해당 버튼이 제공되는 환경에서 사용합니다.
5. 상단 **배치 검토**를 엽니다. 통로 검토 폭을 작업 조건에 맞게 입력하고, 각 항목을 눌러 해당 설비를 수정합니다. 표시된 기본값 1.2m는 변경 가능한 검토 설정입니다.
6. 변경 전 안을 남기려면 **프로젝트 → 설계안 비교**에서 이름을 입력하고 **현재 설계안 보관**을 누릅니다. 배치를 바꾼 뒤 같은 창에서 수량과 점유율을 비교합니다. 보관안 **열기**는 현재 작업을 바꾸며 실행 취소로 돌아올 수 있습니다.
7. **수량표 → 수량표 CSV 다운로드**로 집계를 내려받습니다. **도면 다운로드**에서는 PDF·DXF·SVG·PNG를 선택할 수 있습니다. CAD용 DXF의 좌표 단위는 **mm**입니다.
8. 작업 도면은 **JSON**으로 백업하고, 다른 기기에서 이어 작업하려면 **GitHub 저장**에서 저장소·브랜치·파일 경로를 지정해 저장합니다. 화면의 기기 저장 상태와 GitHub 저장 결과를 각각 확인합니다.

기존 도면 이미지를 기준으로 그릴 때는 WebGL 지원 화면의 **프로젝트 → 배경 도면 · 축척 맞추기**를 사용합니다. PNG/JPEG에서 거리를 아는 두 점을 고르고 실제 거리를 입력한 뒤 설비를 배치합니다.

## 숫자를 읽는 기준

| 표시 | 의미와 해석 |
| --- | --- |
| 팔레트 보관 | 랙 구성과 지정한 바닥 보관 위치로 계산한 설계상 팔레트 위치 수입니다. 현재 입고되어 있는 팔레트 재고 수가 아닙니다. |
| 박스 보관 | 박스 랙과 팔레트 적재 규격 등으로 계산한 보관 가능 위치입니다. 입력한 규격과 설정이 맞는지 먼저 확인합니다. |
| 실제 박스 | **도면에 배치·적재된 박스 개수**입니다. “실제”는 이 도면의 배치 수량을 뜻하며 WMS·ERP 재고와 연결되지 않습니다. |
| 바닥 점유 | 바닥에 놓인 설비 외곽의 면적입니다. 회전과 창고 경계를 반영하고 겹친 면적은 한 번만 셉니다. 구역 표시, 작업자, 받침 위 적층 설비와 공중 설비는 제외합니다. |
| 미점유 면적 | 전체 바닥에서 위 점유 면적을 뺀 값입니다. 통로·피난·작업 여유를 확보한 사용 가능 면적을 뜻하지 않습니다. |
| 수량표의 수량 | 도면에 놓인 객체 수입니다. 구역과 작업자도 목록에 포함되므로 발주 수량으로 사용할 때는 설비 종류를 확인합니다. |

수량표는 설비 종류뿐 아니라 크기·구성·적재 규격도 나눠 집계합니다. CSV에는 한글 Excel 사용을 위한 UTF-8 BOM이 포함됩니다. 출력 전 화면의 수량과 회사에서 사용하는 설비 명세를 대조하세요.

## 저장과 호환 모드

웹앱은 정적 HTTP(S) 페이지로 실행하며 별도의 애플리케이션 서버가 필요하지 않습니다. 로컬 파일을 더블클릭하는 `file://` 실행 대신 GitHub Pages 또는 정적 HTTP 서버를 사용합니다.

| 저장 방식 | 보관되는 곳 | 다른 기기에서 열기 |
| --- | --- | --- |
| 기기 자동 저장 | 현재 브라우저의 저장 공간 | 자동으로 공유되지 않음 |
| 설계안 비교의 보관안 | 현재 브라우저의 저장 공간, 최대 5개 | 자동으로 공유되지 않음 |
| JSON 내보내기 | 사용자가 내려받은 파일 | 파일을 전달한 뒤 불러오기 |
| GitHub 저장 | 지정 저장소의 JSON 파일과 커밋 이력 | 같은 저장소에서 불러오기 |

브라우저 데이터를 삭제하면 기기 저장 도면과 비교용 보관안이 사라질 수 있습니다. 비교용 보관안은 공동 편집이나 클라우드 동기화 기능이 아닙니다. GitHub 저장은 브라우저가 GitHub API를 호출하며 쓰기 권한과 네트워크 연결이 필요합니다. 공개 저장소에 커밋한 도면은 공개되므로 업무 도면은 조직에서 허용한 저장소를 지정합니다.

WebGL 2를 사용할 수 없는 환경에서는 **2D 평면 설계**로 시작합니다. 설비 배치·드래그·속성 편집, 랙 반복 배치, 배치 검토, 수량표, 설계안 비교, JSON/GitHub 저장과 도면 출력을 사용할 수 있습니다. 화면 이동은 `Alt+드래그`, 확대·축소는 마우스 휠입니다. 3D 보기·운영 시뮬레이션·내부 체험과 일부 자동화·배경 편집은 이 모드에서 제공하지 않습니다.

## 배치 검토의 범위

배치 검토는 도면의 기하학적 조건을 검사합니다. 통로 폭은 **통로 객체로 명시한 구역의 짧은 변**을 사용하며, 도면의 모든 빈 공간을 자동으로 통로로 인식하지 않습니다. 겹침과 경계 검사는 입력한 외곽 형상을 기준으로 합니다.

검토 결과가 없다는 것은 현재 설정의 검사 항목에서 문제가 발견되지 않았다는 뜻입니다. 소방·건축·피난·산업안전 적합성이나 랙 구조 강도, 하중, 지게차 회전 공간을 인증하지 않습니다. WebGL 화면의 작업자 운영 기능도 실제 창고 처리량을 보증하는 검증 도구로 사용할 수 없습니다.

## 상용 사례에서 반영한 설계 방향

공식 제품 안내에서 확인한 작업 흐름을 참고해 탐색, 수량 확인, 검토와 결과물 전달을 개선했습니다. 아래 제품의 기능 전체를 이 앱에 구현했다는 뜻은 아닙니다.

| 공식 자료 | 확인한 방식 | 이 워크벤치에 반영한 방향 |
| --- | --- | --- |
| [IntralogisticGrid](https://www.intralogisticgrid.com/) | 2D/3D 전환, 축척을 맞춘 도면 이미지, 팔레트·박스 위치 실시간 확인 | 배치 화면에서 수량과 공간을 함께 확인하고 기존 도면 작업을 이어갈 수 있는 구성 |
| [RackCity 제품 소개](https://www.rackcity.ai/product) | 구역 단위 배치, 설정 변경에 따른 위치 수 갱신, 도면·수량 결과물 전달 | 자동 배치 접근성, 수량표와 도면 다운로드 연결 |
| [RackCity 작업 화면 개편 안내](https://www.rackcity.ai/whats-new/rackcity-v1-3-0-metric-mode-exact-aisle-widths-and-new-workspace) | 편집 패널 정리, 명확한 단위, 지정 통로 폭과 남는 공간의 구분 | 목적별 탭, 선택 설비 속성, 미점유 면적과 통로 검토의 의미 구분 |
| [visTable 기능 안내](https://www.vistable.com/software/) | 설계안과 KPI 비교, 버전 기록, 물류 동선 시각화 | 이름 있는 설계안 보관과 같은 기준의 수량·점유율 비교 |

RackCity의 공식 안내에서 3D는 개별 베이 보기로 설명되며, 전체 창고 내부 체험과는 범위가 다릅니다. visTable은 설치형 제품이며 여기서는 설계안 비교와 업무 결과 전달 방식을 참고했습니다. AI 자동 설계, 견적 산출, 실시간 공동 편집은 이번 워크벤치의 기능으로 안내하지 않습니다.
