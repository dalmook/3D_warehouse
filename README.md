# Warehouse City 10.0 — 업무용 창고 설계 워크벤치

서버를 따로 운영하지 않는 3D 창고 설계 · 작업자 동선 시뮬레이션 · 1인칭 내부 체험 도구입니다.

**실행:** https://dalmook.github.io/3D_warehouse/

## 이번 개선

- **설비 / 자동 배치 / 프로젝트** 탭과 설비 검색, **Ctrl/⌘+K 기능 검색**으로 필요한 작업에 바로 접근합니다.
- **창고 현황**은 팔레트·박스 보관 위치와 실제 배치된 박스를 구분하며, 회전·중복을 반영한 바닥 점유율을 표시합니다.
- **배치 검토**에서 경계·겹침·표시된 통로 폭 문제를 확인하고 해당 설비로 이동합니다.
- **수량표**에서 동일 규격을 집계하고 한글 CSV를 다운로드합니다. **설계안 비교**로 최대 5개 안을 이 브라우저에 보관할 수 있습니다.
- WebGL 2를 사용할 수 없으면 **2D 호환 편집기**가 자동으로 열립니다. 도면 편집·저장·출력은 계속 사용할 수 있으며 3D·운영·내부 체험 등 지원하지 않는 기능은 명확하게 비활성화됩니다.
- 저장 공간 부족 때 정상 도면을 읽지 못하던 문제, 박스 꺼내기·회전 중 수량 중복, 잘못된 추가 작업 후 원본 변형을 수정했습니다.

상용 사례 조사, 사용 순서 및 계산 범위: [워크벤치 가이드](docs/WORKBENCH-10.md).

## 처음 사용하기

1. **01 설계**에서 예제 또는 빈 창고로 시작합니다. 설비를 고른 뒤 바닥을 클릭해 배치하고, 선택한 설비의 위치·규격·색상·랙 구성을 오른쪽에서 조정합니다. 랙 일괄 배치와 실행 취소/다시 실행을 지원합니다.
2. 작업자와 작업 지점을 놓고 **02 운영 → 실행**을 누릅니다. 작업자는 작업 지점의 배치 순서를 순환하며 장애물을 피해 이동합니다. 보행 속도·작업 대기 시간·배속을 조정할 수 있습니다.
3. **03 내부 체험**으로 전환해 창고 안으로 들어갑니다. 실행 중인 작업자도 계속 움직입니다. PC는 WASD/방향키, Shift, 화면 드래그 또는 마우스 잠금으로 조작합니다. 휴대폰은 방향 버튼과 화면 드래그를 사용합니다.
4. 상단 **GitHub 저장**에서 저장소와 경로를 지정해 저장합니다. JSON 파일 저장/불러오기도 가능합니다.

## 서버 없는 저장

웹 화면은 GitHub Pages의 정적 파일이고, GitHub 저장은 브라우저가 GitHub Contents API를 직접 호출합니다. 별도 Node/Python 서버, 데이터베이스, S3, Cloudflare 또는 유료 저장 서비스는 필요하지 않습니다.

- **브라우저 자동 저장:** 현재 기기·브라우저의 localStorage에 보관합니다. 브라우저 데이터 삭제나 다른 기기에서는 유지되지 않습니다.
- **GitHub 저장:** 도면 JSON이 지정한 저장소/브랜치/경로에 커밋됩니다. 다른 기기에서 불러올 수 있고 GitHub 변경 이력이 남습니다.
- GitHub에 쓸 때는 해당 저장소의 `Contents: Read and write` 권한을 가진 Fine-grained PAT를 저장 창에 입력합니다. 공개 도면 조회에는 보통 토큰이 필요하지 않습니다. 토큰을 채팅·소스·도면에 붙여 넣지 마세요.
- 토큰은 저장 창의 메모리에만 존재하며 창을 닫으면 지워집니다. localStorage, sessionStorage, JSON, URL에 저장하지 않습니다.
- 기존 파일은 SHA를 대조하며, 다른 사용자가 바꾼 도면을 무조건 덮어쓰지 않습니다. 충돌 시 현재 작업을 JSON으로 보관한 뒤 최신 파일을 다시 불러오세요.
- 현재 `dalmook/3D_warehouse`는 공개 저장소입니다. 여기에 저장한 도면은 공개됩니다. 회사 기밀·실제 보안 설비 정보는 승인된 비공개 저장소를 지정하고 조직의 데이터 정책을 확인하세요.

## 기존 도면

기존 정밀 편집기는 [classic.html](./classic.html)에 유지됩니다. 기존 저장 키 `warehouse-studio-project-v1` 및 `layouts/` 파일을 삭제하거나 자동 덮어쓰지 않습니다. 새 편집기는 별도의 `warehouse-city-v9` 저장 공간을 씁니다. 구버전 JSON은 변환하여 새 화면에 불러올 수 있지만 특수 설비 표현은 단순화될 수 있으므로 원본 JSON을 별도로 보관하세요.

기존 `objects.js`가 함수 중간에서 잘려 구버전이 실행되지 않던 문제를 원본 V7 배포본의 누락된 부분으로 복구했습니다. 기존 41,472바이트 접두부는 원본과 완전히 동일했고, 복구된 전체 파일의 SHA-256은 `afdb81c8c42c7774d641bcfea95f83b0d580cf51acdd23bea077768cdd0e694a`입니다. S3 브릿지나 서버 프로그램은 복원하지 않았습니다.

## 범위와 한계

새 화면의 창고 크기는 가로·세로 10~200m, 높이 3~30m, 최대 설비 600개, 시뮬레이션 작업자 40명입니다. 실시간 다중 사용자 편집이나 실제 작업자 위치 추적은 아닙니다. 작업자는 가상의 동선 애니메이션이며 작업자끼리의 충돌, 지게차 배차, 대기열·실제 처리량을 검증하는 산업용 시뮬레이터는 아닙니다. 통로·소방·건축·안전 적합성 판단을 대신하지 않습니다.

## 개발 및 검증

- 실행: 정적 HTTP 서버 또는 GitHub Pages. ES 모듈 때문에 `file://` 더블클릭 대신 HTTP(S)를 사용합니다.
- 핵심 검사: `node --test city-core.test.mjs tests/core-release.test.mjs`
- 브라우저 검사: Playwright Chromium의 실제 WebGL, 포인터·키보드·모바일 터치 시나리오.
- 실제 저장 검사: Actions 임시 토큰으로 합성 도면을 임시 브랜치에 생성·수정·불러온 뒤 브랜치를 삭제합니다. 사용자의 도면과 실제 토큰은 테스트 자료에 넣지 않습니다.
- 배포 검사: 공개된 HTML/JS/CSS의 SHA-256을 소스와 비교한 뒤 같은 브라우저 검사 및 저장 검사를 공개 사이트에서 다시 실행합니다.
- 최신 결과는 GitHub Actions의 **Warehouse City browser QA and Pages** 실행 결과와 첨부된 QA 자료가 기준입니다. 휴대폰 실기기/모든 GPU 검증 완료를 뜻하지 않습니다.

기존 Pages 설정이 `main / (root)`이면 해당 자동 배포를 유지합니다. Pages가 GitHub Actions 방식이면 워크플로가 정적 파일을 모아 배포합니다. 앱 코드는 어느 방식이든 동일하며 별도 애플리케이션 서버를 운영하지 않습니다.
